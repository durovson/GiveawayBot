# GiveawayBot

Telegram-бот для розыгрышей, RP-экономики, TON Connect, реферальной программы,
магазина билетов, каталога ограниченных лотов, GRAM-пополнений и OTC Offers.

## Локальный запуск

1. Создайте виртуальное окружение и установите зависимости:

   ```powershell
   py -m venv .venv
   .\.venv\Scripts\python.exe -m pip install -r requirements.txt
   ```

2. Скопируйте `.env.example` в `.env` и заполните значения. Для
   `SUPABASE_KEY` бот должен использовать серверный `service_role` ключ: таблицы
   защищены RLS и не предназначены для прямого доступа клиента.

3. Последовательно примените SQL из `migrations/20260817_store_lots.sql` и
   `migrations/20260828_economy_v2.sql` в Supabase SQL Editor.

4. Запустите бот:

   ```powershell
   .\.venv\Scripts\python.exe bot.py
   ```

## Магазин

Главный экран Store разделён на два независимых сценария:

- Tickets — временные шансы для конкретного активного giveaway, включая один
  бесплатный билет и максимум 10; наборы и цены задаются в `ticket_offers`;
- Lots — динамические товары из `store_lots` с ценой, остатком, лимитом на
  пользователя и типом награды.

Администраторы из `ADMIN_IDS` получают кнопку управления магазином. Через неё
можно создать лот по короткому сценарию «название → описание → цена → preview»,
опубликовать или отключить его и обработать заказ, требующий ручной выдачи.

Покупки выполняются SQL-функциями в одной транзакции. В ней одновременно
проверяются баланс, остаток и пользовательский лимит, списываются RP через
`spent_points`, создаётся запись покупки и обновляется количество. Повторный
Telegram callback безопасен благодаря `idempotency_key`.

## Новые таблицы

- `store_lots` — каталог и складской остаток;
- `store_purchases` — заказы и история выдачи;
- `points_transactions` — журнал списаний RP для аудита.
- `giveaway_ticket_balances` и `ticket_offers` — билеты и настраиваемые пакеты;
- `gram_deposits` — идемпотентный журнал подтверждённых GRAM-переводов;
- `otc_listings` и `otc_offers` — объявления и переговорные предложения.

`points.total_points` остаётся вычисляемым остатком. Источники заработанных RP
дополнены `external_points`, а покупка увеличивает `spent_points`, поэтому следующий
`recalculate_points()` не возвращает уже потраченные баллы.

## GRAM и OTC

Для GRAM задаются `TONAPI_KEY`, `GRAM_DEPOSIT_WALLET` и
`GRAM_JETTON_MASTER`. Перевод от 0.1 GRAM с комментарием `@username`
проверяется через TonAPI и может быть начислен только один раз. Курс хранится
в `settings.gram_rp_per_gram`.

OTC-публикация содержит deep link Offer и профиль владельца. Оффер сохраняется
в БД, но пяти минутный cooldown хранится только в памяти процесса. Бот не
проводит расчёты и после Accept/Decline лишь уведомляет обе стороны.

## Проверка

```powershell
.\.venv\Scripts\python.exe -m compileall .
```

Миграция также содержит атомарные функции участия в розыгрыше и фиксации его
завершения. Они устраняют двойное списание билетов и повторное завершение при
одновременных callback или фоновых задачах, не меняя пользовательские цепочки
сообщений.
